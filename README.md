# ETS2 자율주행 연구

이 공개 저장소에는 자체 DLL·Python 소스, 설계·분석 문서, 연구 스크립트와 라이선스를 보존한 의존 코드가 들어 있습니다. 개발 중인 연구 프로젝트이며 빌드·실험 상태는 [ot 문서](ot/README.md)를 기준으로 확인합니다.

RenderDoc 실행 설정은 `research/ets2-mirrors.cap.example`을 `research/ets2-mirrors.cap`으로 복사하고 게임 경로를 수정해 사용합니다. 개인 설정 사본은 Git에서 제외됩니다.

게임 파일·추출 자산, 공식 SDK 원본, 다운로드한 도구·참고 저장소, 원시 메모리 기록·RenderDoc 캡처·GPU 배열, 빌드 결과와 로컬 백업은 Git에서 제외합니다. 문서의 `research/live/`·`research/findings/` 자료 링크 일부는 로컬 실험 자료를 가리키며 공개 저장소에는 없습니다. 빌드에는 별도 ETS2 설치와 [공식 SDK](https://modding.scssoft.com/wiki/Documentation/Engine/SDK)가 필요합니다. 의존 코드의 라이선스와 고정 revision은 [THIRD_PARTY](ot/THIRD_PARTY.md), 빌드 방법은 [ot 사용법](ot/README.md)에 있습니다. 문서·스크립트의 Windows 경로는 원래 연구 PC 기준이므로 자신의 설치 경로에 맞춰야 합니다.

**2026-10-08 구현 상태:** 0.7.0 상주 메타로더가 기능 DLL을 외부 API로 교체합니다. 기능 모듈 0.8.3은 미러 0·1·2·5의 RGB·카메라 Z·재질·실제 깊이 버퍼를 같은 Present 구간으로 수집합니다. 명령 구간을 통해 CPU pass 카메라와 GPU geometry 상수를 연결해 회전·투영도 대조했습니다. Python의 `reconstruct` 명령은 저장된 DSV 또는 shader Z를 골라 카메라·월드 점군을 만듭니다. 잎 shader가 Z를 별도로 보정하는 경로도 확인했습니다. mirror5는 5초·50표본·10 Hz 기록을 확인했습니다. SDK 9채널, 내부 자차 자세 대조, hook 시간 계측·읽기 비용 감소, hook 복원과 DLL 해제도 실제 게임에서 확인했습니다. `project_boxes`는 저장된 영상에 외부 객체 박스를 투영하고 깊이로 가림을 구분합니다. 주차 트럭 한 대의 두 미러 정합을 확인했습니다. 0.8.3은 선택적으로 미러 draw 목록과 AI·주차 차량 모델을 연결해 렌더 자세와 simulation actor 자세를 함께 기록하며, 다음 작업은 움직이는 AI의 렌더 시각 정합·주행 검증 및 센서 데이터 전달입니다. [빌드·설치·사용법과 실측 기록](ot/README.md), [전체 M0–M6 계획](docs/13_game_operating_table.md)을 참고하세요.

2026년 10월 8일 기준. RTX 3060 Ti와 FHD 모니터 한 대에서 ETS2 운전석 화면을 유지하고, 차체에 고정한 4~6개 카메라로 BEV와 E2E 자율주행을 실험하기 위한 작업 문서입니다.

핵심 방향은 미러·디지털미러·주차 카메라의 기존 렌더 경로를 역추적해 독립 센서 뷰를 만드는 것입니다. 카메라 객체 접근, 추가 미러 구성, 텍스처 후킹의 공개 선례는 있습니다. 현재 게임 빌드에서 임의의 6개 센서 뷰를 생성하는 함수와 성능은 아직 확인되지 않았습니다.

설치된 **ETS2 1.61.1.1 / Steam build 25482642**에 대한 기초 오프라인 분석을 완료했습니다. 게임 정의·미러 UI·재질을 추출했고, 공식 SDK 채널 108개와 ETS2LA 공유 메모리 계약을 정리했습니다. ETS2LA Windows 패턴 11개 및 기존 카메라 함수 후보를 실제 실행 파일과 대조했습니다.

초기 DX11 수동 주행과 도로 정차 중에는 **외부 읽기 전용 메모리 관측**을 수행했습니다. 내 트럭의 위치·속도·조향, 주변 AI, 주차 차량 21개, 신호등 29개와 차단기 2개를 읽었습니다. 별도 소유 구조에 있는 **실제 미러 카메라 6개와 텍스처 descriptor 7개**를 찾아 pose·projection·게임 재질 이름까지 연결했습니다. 이 초기 조사는 DLL·입력·메모리 쓰기 없이 수행했으며, 이후 DLL에서 픽셀 수집으로 확장했습니다. 초기 실측은 [도로 상태 데이터 문서](docs/11_idle_memory_and_telemetry.md)에 있습니다.

후속 조사에서 **미러 4개의 실제 DX11 색상·깊이 텍스처**까지 연결했습니다. 미러 0·2의 중간 리소스 재사용, 셰이더의 Z 복원식과 실제 복원 상수도 확인했습니다. 미러별 렌더 작업의 투영행렬·viewport·기본 카메라 자세·ray를 연결했으며, reversed Z와 0.01–0.9 깊이 범위, main 실내의 별도 범위·투영을 구별했습니다. 후속 원본 렌더 객체 표본에서는 카메라·ray를 덮어쓰는 추가 상태와 카메라 변환을 무시하는 필터가 발견되지 않았습니다. 이 정적·외부 관측 이후 RenderDoc과 DLL로 픽셀을 확보했습니다. DLL 영상과 같은 pass의 최종 상수 연결은 다음 작업입니다. 최신 결과는 [DX11 미러 렌더 경로](docs/12_dx11_mirror_render_path.md), 일반 객체 실측은 [도로 정차 상태 데이터](docs/11_idle_memory_and_telemetry.md)에 있습니다. 참고 소스·SDK·추출본은 [research](research/README.md)에 있습니다.

추가로 미러 생성·갱신·제출의 9슬롯 제한과 원본 카메라·출력의 의존성을 확인했습니다. 관측된 일반 미러 모드 0은 현재 운전석 위치로 반사 방향을 계산합니다. 디지털미러 모드 1에는 사용자 좌석 보정 전의 기준 위치를 사용하는 경로가 있으며, 좌석 조절 UI에서도 기준과 보정이 분리됩니다. 이 결과는 코드 추적이며 디지털미러 영상의 차체 고정 여부나 추가 센서 렌더를 실행한 검증은 아닙니다. 독립 센서의 자세 생성과 활성 조건은 여전히 구현·실측 대상입니다.

미러의 공통 parent는 본체 자세에 캐빈 서스펜션의 상대 자세를 합성합니다. 두 자세의 이력과 렌더 시각을 이용하는 보간 버퍼도 찾았고, CPU 표본에서 합성·위치 보간 관계를 대조했습니다. SDK 차량 자세와 엔진 렌더 본체 이력의 기준점은 같지만, ETS2LA camera record는 별도로 경계 상자 중심을 더합니다. 샤시에 고정할 센서와 캐빈에 장착할 센서는 기준을 구별해야 하며, GPU 영상과 같은 프레임으로 수집하는 작업은 남아 있습니다. 또한 맵 Model 147개를 렌더 객체를 통해 주 화면·미러의 CPU 수집 목록까지 연결했습니다. 후속 조사에서는 다섯 종류의 미러 제외 설정이 공통 플래그로 변환되고 실제 미러 후보 선택에서 거부되는 코드까지 확인했습니다. 공통 표 2,481개 중 관련 항목 1,527개 모두에서 원본 설정과 변환 결과가 일치했고 제외 대상은 64개였습니다. 거리별 LOD와 재질 선택은 별도 단계이며, GPU 영상의 실제 물체 누락은 아직 비교하지 않았습니다.

주차 차량 21개의 배치점·차량 객체·렌더 모델도 연결했습니다. 19개는 독립 Hookup, 2개는 Prefab에 붙은 객체입니다. Hookup의 미러 제외 설정이 생성된 모델에 전달되고 실제 미러 제출 단계에서 다시 검사되는 경로까지 확인했습니다. 설정이 켜진 표본 1개는 LOD 조건에서도 제외된 상태였으므로, 미러 설정만으로 영상 누락이 발생한 실험 결과는 아닙니다. AI 차량 모델 50개와 그중 8개에 연결된 trailer 모델 35개도 추적했습니다. 연결 모델은 공통 활성 목록에 직접 등록되지 않고 부모에서 호출되며, 각자의 LOD와 미러 제외 조건을 검사합니다.

차량의 기본 LOD는 개별 미러가 아닌 현재 선택된 게임 카메라와의 수평 거리를 기준으로 계산하며, 주 화면에만 FOV 보정을 추가합니다. 실제 거리 배율·경계 배열·미러 품질 설정까지 읽었습니다. 독립 센서에서는 카메라 위치뿐 아니라 이 상세도 기준도 분리할 필요가 있습니다.

거리 계산 전의 차량 표시 조건도 소속 도로까지 연결했습니다. 차량·연결 모델 85개에서 계산한 조건과 읽은 표시 상태가 일치했고, 표시가 꺼진 23개 중 16개는 도로 제외 상태, 7개는 소속 경로 포인터가 NULL이었습니다. 도로의 cut plane 공간 판정도 현재 core 목록의 26개 표본과 일치했습니다. cut plane 64개와 Visibility area 48개의 상태 역시 선택된 게임 카메라 기준이었으며, 영역별 객체 포함·제외 예외와 갱신 순서도 연결했습니다. 따라서 독립 센서는 자세·LOD뿐 아니라 도로 단위의 대상 선택도 확인해야 합니다. 이 결과는 외부 읽기와 코드 분석이며 GPU 픽셀 누락을 직접 관측한 것은 아닙니다.

움직이는 배경 객체 중 인물 3개의 실제 모델 경로와 거리별 모델 선택도 대조했습니다. 이 경로는 게임 카메라와의 3차원 거리·FOV로 모델 하나를 고르고 각 렌더 뷰에서 구 경계로 시야를 검사합니다. 인물도 독립 센서 기준의 상세도·거리 숨김을 고려해야 하며, 모든 보행자 종류나 GPU 픽셀까지 확인한 결과는 아닙니다.

프레임의 상위 호출 순서도 연결했습니다. 약 16.666 ms의 simulation step 안에서 AI 사전 갱신, 물리 처리（PhysX 결과 대기 포함）, 사후 갱신, SDK 데이터 전달이 진행됩니다. 그 뒤 자세 이력 발행·보간, 카메라, 도로 가시성, 인물·차량 LOD, 미러 목록·장면 준비가 이어집니다. **SDK `frame_end`는 GPU 렌더 완료 시점이 아닙니다.** 기존 FFB 플러그인의 등록 채널 44개와 선택 5채널의 내부 값도 읽었습니다. SDK world placement와 속도 벡터는 물리 body를 읽으며 렌더 보간 자세와 별도 경로입니다. 선형 속도는 질량중심 기준이고, 현재 트럭의 SDK 위치 원점은 그 점에서 약 0.78 m 떨어져 있어 센서 장착점 속도에는 회전 보정이 필요합니다. 선형 가속도는 10-step 이동평균이고, 현재 약 167 ms 구간을 반영합니다. AI 판단도 별도의 배치 처리 경로를 사용합니다. 영상과 텔레메트리를 같은 프레임으로 수집하는 작업은 남아 있습니다.

## 현재 결정

- 개발과 게임 실행은 Windows 네이티브를 기준으로 합니다.
- ETS2가 주 프로젝트이며 ATS는 추후 이식 후보입니다. AC는 별도 실험입니다.
- 운전석 POV와 센서 카메라를 분리합니다. 사용자 고개 움직임이 센서를 회전시키면 안 됩니다.
- 센서는 4~6뷰이며 전방 전용 카메라를 포함합니다. 720p는 목표 해상도이고 실측 전 보장은 없습니다.
- 게임 감속과 프레임마다 카메라를 전환하는 수집은 제외합니다.
- 한 센서 묶음은 하나의 렌더 장면 상태를 공유합니다.
- 첫 기술 목표는 기존 보조 카메라 영상 추출 후, 독립 정면 센서의 생성과 RGB·depth 정합입니다.
- 모델 학습보다 센서 생성과 시간·좌표 정합을 먼저 확보합니다.

## 사실과 제안의 구분

공식 문서·소스에서 확인한 내용, 모더의 경험 보고, 이 프로젝트의 설계 제안을 구분했습니다. main 브랜치 링크는 바뀔 수 있습니다. 실제 개발을 시작할 때 사용할 게임 빌드와 관련 저장소 commit을 함께 기록해야 합니다.

`research`에는 로컬 SDK·도구·참고 소스·추출본·메모리 및 GPU 실측 기록이 있습니다. 현재 픽셀 자료는 주로 차고 정차 표본이며, 학습용 주행 데이터셋은 아직 없습니다. 약 30 Hz 제출 간격의 초기 실험에는 백그라운드 FPS 제한이 적용됐을 가능성이 있어 hook 자체 비용과 GPU 여유를 다시 측정합니다. 추출 게임 파일과 원시 실험 자료는 Git 추적에서 제외합니다.
