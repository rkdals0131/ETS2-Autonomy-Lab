# 30. 실차 CAN에 해당하는 신호

2026-10-20, 게임 1.61.1.9, core 0.39.0–0.41.0, Scania S 6x2 태그리프트(DC16 520, G33CM-R, [docs/29](29_reference_truck_dynamics.md)). 실제 트럭 CAN(J1939)이 내보내는 엔진·변속·제동 신호를 게임에서 어디서 얻는지 정리합니다. 세 출처가 있습니다.

1. SDK 채널(core 0.37.0부터, Tier 0): 회전수·기어·페달·온도·압력·연료·리타더 단·엔진브레이크 플래그 등.
2. 차량 물리 메모리(core 0.39.0, Tier 1): SDK에 없는 실제 엔진 토크, 변속기 출력 토크·회전, 바퀴별 브레이크 토크.
3. def 파일(정적 사양, EC1에 해당): 토크 곡선, 기어비, 리타더 단별 구성, 축하중, 타이어, 전역 물리 상수. [research/truck_spec.py](../research/truck_spec.py)가 세이브의 현재 트럭 부품으로 골라 줍니다.

ROS에는 `/ets2/vehicle/powertrain`(ets2_msgs/PowertrainState, 0.3.0)으로 1과 2를 함께 냅니다. 2는 릴레이가 Tier 1일 때만 채워지고(`drivetrain_available`), 없으면 NaN입니다. sysid 하네스는 실행 동안 Tier 1을 켜고 프레임마다 `dt`에 2를 기록합니다.

| J1939 | 신호 | 출처 | 단위·비고 |
|---|---|---|---|
| EEC1 | 엔진 회전수 | SDK `truck.engine.rpm`, Tier 1 `engine_speed_radps` | 같은 값(r 1.000) |
| EEC1 | 실제 엔진 토크 | Tier 1 `engine_torque_nm` | Nm. 음수는 마찰(약 −270 Nm)·엔진브레이크(약 −3,000 Nm) |
| EEC1/EEC2 | 운전자 요구 토크·가속 페달 | SDK `truck.input.throttle`·`truck.effective.throttle` × def 토크 곡선 | 요구 토크는 계산값 |

## 메모리 위치와 찾은 방법

플레이어 vehicle(스키마 controller → player actor → +0x18)에서 시작합니다. 오프셋은 `ot/schema/1.61.1.9/fields.json`의 `vehicle_drivetrain`입니다.

| 값 | 위치 |
|---|---|
| 구동계 물리 객체 P | vehicle+0x150 → |
| 엔진 각속도, 출력축 각속도 | P+0x2e0, P+0x2ec (rad/s) |
| 엔진 토크, 변속기 출력 토크 | P+0x2f4, P+0x2d4 (Nm) |
| 기어비, 클러치 | P+0x2c4, P+0x330 |
| 바퀴별 브레이크 토크 | P+0x260 → float[바퀴 수] |
| 계기 객체 Q | vehicle+0x1820 → |
| 리타더 비율, 엔진브레이크 | Q+0x3e8, Q+0x3f0 |
| 첫 트레일러 차량 객체 | vehicle+0x15a8 → (트럭과 같은 구조: +0x150 → +0x260 → 바퀴별 브레이크 토크) |

[research/can_scan.py](../research/can_scan.py)가 vehicle과 그 포인터 대상 2단계(2,279개 객체, 2.3 MB)를 5 Hz로 읽으면서 SDK 채널과의 상관을 누적하고, [research/can_probe.py](../research/can_probe.py)가 후보 객체를 30 Hz로 다시 읽어 모든 SDK 채널과 대조했습니다. 둘 다 `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`만 씁니다. 원자료는 `research/live/2026-10-20-can-scan`, `-can-probe`, `-can-probe-brake`(git 제외)입니다. 게임이 업데이트되면 이 오프셋은 `rebase_rvas.py`가 옮기지 않으므로 두 스크립트로 다시 확인합니다.

## 물리 검증

- ✔ 출력 토크: 변속·클러치 구간을 뺀 4,054개 표본에서 `output_torque × 2.59 / 0.506 − 3.0·v² = m·a + c·m·g`를 맞추면 R² 0.946, m 11,967 kg, 구름 저항 c 0.0072입니다. def 타이어 구름 저항(앞 6.5, 뒤 7.5 kg/t)과 맞고, 질량은 축 kerb 9,820 kg + 캐빈 700 kg + 연료 약 900 L(약 760 kg) + 회전 관성 등가와 맞습니다. 같은 식을 엔진 토크 × 기어비로 하면 R² 0.918입니다.
- ✔ 엔진 토크: 전부하에서 1,600–2,000 rpm은 def `2700 × torque_curve`와 1 % 안에서 같습니다(2,129 대 2,137, 1,985 대 1,988 Nm). 1,000–1,600 rpm은 변속 직후 과도 구간이 섞여 더 낮게 나옵니다.
- ✔ 마찰 토크: 스로틀 0, 엔진브레이크 꺼짐, 클러치 연결에서 800–1,600 rpm에 −265 ~ −287 Nm입니다(자동 변속 자료). 회전수 전 구간은 아래 [기어 고정 맵](#기어-고정-맵-2026-10-20-시퀀셜-트레일러-연결)에서 −264 ~ −330 Nm로 회전수에 비례합니다.
- ✔ 엔진브레이크: −3,024 Nm(2,000–2,200 rpm). 자동 변속기가 엔진브레이크 동안 이 회전수를 유지해 다른 회전수 자료는 없습니다. 기어별 엔진브레이크 감속은 이 토크 × 기어비 × 2.59 / 0.506 / m로 나옵니다.
- ✔ 리타더: def `auxiliary_brakes`가 단별 (비율, 엔진브레이크 여부, 셋째 값)을 정합니다. 셋째 값의 의미는 모릅니다(5단만 1). G33CM-R은 0.2, 0.4, 0.6, 0.8, 그리고 5단은 1.0과 엔진브레이크입니다(docs/29의 "5단 = 리타더 + 엔진브레이크" 측정과 일치). 출력축에서 본 리타더 토크(Nm)는 출력축 회전에 거의 비례합니다.

| 출력축 rad/s | 40–60 | 60–80 | 80–100 | 100–120 |
|---|---|---|---|---|
| 1단 | −115 | −231 | −313 | −400 |
| 2단 | −351 | −564 | −786 | −952 |
| 3단 | −574 | −931 | −1,291 | −1,577 |
| 4단 | −895 | −1,329 | −1,842 | — |

  계산식의 0.905는 타력에서 잰 `output_torque / (engine_torque × gear_ratio)` 중앙값입니다.
- ✔ 브레이크 토크: 브레이크 1.0에서 앞바퀴 28.3 kNm, 구동축 24.0 kNm, 태그축 9.4 kNm까지(태그 올림 상태). def 물리의 `brake_balance 1.1`(앞이 더 셈)과 방향이 같습니다.

## 정적 사양(EC1에 해당)

`py -3 research/truck_spec.py`는 프로필의 최신 세이브를 복호하고(research/savedec, TruckLib), SDK 트럭 구성과 맞는 소유 트럭 중 주행거리가 가장 긴 트럭을 골라 def를 모드 우선 순서로 읽습니다. 현재 레퍼런스 트럭 결과:

- 엔진 DC16 520: 2,700 Nm, 곡선 (300, 0.1) (440, 0.4) (1000–1300, 1) (1600, 0.82) (1900, 0.72) (2300, 0.4) (2500, 0.1).
- 변속기 G33CM-R: 14+8단, 종감속 2.59, 변속 시간 0.7 s, 리타더 5단.
- 섀시 6x2 롱 태그리프트: 축 kerb 5,650 / 2,383 / 1,787 kg(합 9,820), 구동 2축, 리프트 3축. Realistic Truck Physics 9.2가 섀시 서스펜션(residual travel 0.17 / 0.088 / 0.088)을 바꿉니다.
- 타이어: 구름 저항 앞 6.5, 뒤 7.5 kg/t, 젖은 노면 접지 0.9(비가 오면 마찰이 바뀌는 근거).
- 전역 물리(RTP 9.2가 덮어씀): 공기 저항 3.0·v², 브레이크 최대 온도 200 °C, 브레이크 균형 1.1, 횡 bristle 강성 ×1.15. 엔진·브레이크·리타더 관련 값은 기본 게임 그대로입니다.

## 기어 고정 맵 (2026-10-20, 시퀀셜, 트레일러 연결)

[apps/sysid/gear_test.py](../apps/sysid/gear_test.py)로 6·8·10·12단을 고정하고 900–2,250 rpm을 쓸었습니다(`gear-20261020-151650`, [analyze_gear.py](../apps/sysid/analyze_gear.py)). 엔진 토크는 차량 메모리의 실제 값입니다.

| rpm | 950 | 1,150 | 1,450 | 1,750 | 2,050 | 2,250 |
|---|---|---|---|---|---|---|
| 마찰(스로틀 0) Nm | −264 | −274 | −289 | −305 | −320 | −330 |
| 엔진브레이크 Nm | −2,060 | −2,972 | −2,989 | −3,005 | −3,020 | −2,954 |
| 전부하 Nm (사양) | 2,535 (2,555) | 2,699 (2,700) | 2,456 (2,457) | 2,078 (2,079) | 1,615 (1,620) | 1,238 (1,188) |
| 스로틀 0.5 Nm(10단) | 1,486 | 1,531 | 1,352 | 1,114 | 838 | 621 |

- ✔ 마찰은 회전수에 거의 비례합니다(약 −217 − 0.05·rpm Nm). 엔진브레이크는 1,100–2,200 rpm에서 약 −3,000 Nm로 평평하고 1,100 rpm 아래에서 줄어듭니다. 전부하는 사양 `2700 × torque_curve`와 같습니다.
- ✔ 스로틀 0.5의 정상 토크는 전부하의 53–58 %로, 회전수가 낮을수록 큽니다. [Simulink 종방향 모델](../apps/sysid/matlab/longitudinal/README.md)의 맞춤으로 보면 `토크 = 마찰 + f(스로틀)·(전부하 − 마찰)`, `f ≈ 1 − (1 − 스로틀)^1.33`(0.5 → 0.60) 하나로 회전수와 무관하게 맞고, 회전수에 따른 비율 차이는 마찰 몫 때문입니다.
- ✔ 토크 응답: 적용 스로틀은 0.07 s 안에 따라오지만 엔진 토크는 늦습니다. 전부하 계단은 63 % 0.5–0.73 s, 90 % 0.8–1.2 s, 스로틀 0.5는 0.35–0.38 s, 0.55–0.6 s입니다. 상승폭이 클수록 오래 걸려 1차 지연보다 상승률 제한(터보 지연에 해당)에 가깝습니다. 상승률은 일정하지 않아 Simulink 모델은 (토크, 회전수) 표로 둡니다: 800 rpm 1,400–1,900 Nm/s, 1,250 rpm 이상 3,400–3,900 Nm/s, 높은 토크 쪽에서 1,800–2,500 Nm/s.
- ✔ 변속기 효율과 관성: 클러치가 붙은 4개 단의 16,888 표본에서 `출력 토크 = η·기어비·(엔진 토크 − J·엔진 각가속도)`를 맞추면 η 0.933, J 5.75 kg·m²(엔진 쪽으로 환산한 플라이휠과 변속기), R² 0.972입니다. 앞 절의 리타더 토크 계산(효율 0.905 고정, 관성 항 없음)은 저단에서 관성 몫이 섞이므로 이 식으로 다시 계산해야 합니다. 각가속도를 매끄럽게 미분해 다시 맞추면([Simulink 종방향 모델](../apps/sysid/matlab/longitudinal/README.md)) 출력 토크 채널은 η 0.972, J 16.0 kg·m²로 R² 0.9996(잔차 rms 33 Nm)을 따릅니다. 그런데 차속을 설명하는 실제 구동 관성은 J 4.6 kg·m²입니다(같은 실행을 출력 토크로 맞춘 질량이 저단일수록 작아짐, 6단 14.5 t). 출력 토크 채널은 게임 안의 보고용 계산이고 실제 구동력과 같지 않으니, 동역학에는 엔진 토크 × 기어비와 J 4.6을 씁니다.

## 브레이크와 리타더 다시 보기 (2026-10-20 저녁)

- ✔ 브레이크 지연: 바퀴 브레이크 토크는 명령 다음 프레임(1/60 s 안)에 목표값이 됩니다(`brake-20261020-152718`, `sysid-20261020-153130`·`-144933`의 모든 계단). 앞에서 잰 "첫 −0.3 m/s까지 0.15–0.35 s"는 지연이 아니라 그 속도가 줄어드는 데 걸린 시간입니다. 모델에는 압력 지연을 넣지 않습니다.
- ✔ 저속 제동 곡선: 같은 입력에서 바퀴 각속도 0–5 rad/s(약 9 km/h 아래)의 토크가 10–30 rad/s보다 약 1.6배 큽니다(0.2: 29.8 대 18.3 kNm, 0.3: 47.9 대 29.6 kNm 합계). 사양 물리 `braking_curve_peak_rel 1.5`의 효과로 봅니다. 5–30 rad/s 사이는 거의 평평합니다(0.3: 26.6 → 25.3 kNm).
- ✔ 입력별 트럭 바퀴 토크 합(트레일러 연결, 10–30 rad/s): 0.1 → 9.0, 0.3 → 25.6, 0.5 → 40.2 kNm. 트럭 단독 0.3은 29.6 kNm로, 같은 입력에서 트럭 쪽 몫이 트레일러 연결 때 조금 작습니다.
- ✔ 트레일러 바퀴 브레이크: 트럭 vehicle+0x15a8이 트레일러 차량 객체이고 구조가 트럭과 같습니다. 40 km/h에서 트레일러 브레이크 키(텐키 0)만 누르면 트레일러 바퀴마다 8.1–9.5 kNm, 트럭 0입니다. 서비스 브레이크 0.2는 트레일러 바퀴마다 4.5–4.8 kNm, 트럭 앞 5.0 / 구동 4.1 / 태그 1.6 kNm입니다(`research/live/2026-10-20-trailer-brake-*`, [research/trailer_brake_drive.py](../research/trailer_brake_drive.py)).
- ✔ 리타더 토크(관성 항 포함): `리타더 토크 = 출력 토크 − 0.933·기어비·(엔진 토크 − 5.75·엔진 각가속도)`로 다시 계산하면 트럭 단독 자동 변속 자료(`can-probe`)와 트레일러 기어 고정 자료(`gear-20261020-151650`)가 기어와 무관하게 맞습니다. 출력축에서 본 토크(Nm)입니다.

## 트레일러와 구성 (core 0.40.0)

- SDK 채널: `trailer.0.connected`, `trailer.0.world.placement`, `trailer.0.velocity.linear`·`angular`, `trailer.0.acceleration.linear`, `trailer.0.cargo.damage`, 바퀴별 `trailer.0.wheel.on_ground`·`angular_velocity`·`suspension.deflection`·`lift`. 트럭 위치와 트레일러 위치로 히치 각을 직접 구할 수 있습니다(실차라면 추정해야 하는 값).
- `ot.cmd configs`(파이프 명령 `configs`): 트럭 외 SDK 구성을 id별로 돌려줍니다. `trailer.0`(바퀴 위치·반경·리프트 가능 여부, 히치 위치, 차체 종류), `job`(화물 id·질량, 작업이 없으면 빈 값), `controls`(`shifter.type`: 자동은 `automatic`, 시퀀셜은 `manual`), `hshifter`, `substances`.
- 2026-10-20 확인: 개인 트레일러 `vehicle.scs.box`(냉동 박스, 3축 6바퀴, 첫 축만 리프트 가능). 트레일러 좌표에서 히치 z −5.07 m, 축 z 1.54·2.86·4.16 m라 히치에서 가운데 축까지 약 7.9 m입니다. 작업이 없어 빈 트레일러이고 화물 질량도 없습니다.

## 남은 것

- 순간 연료율, ABS·ESC 플래그, 엔진 부하율(EEC2)은 확정하지 못했습니다.
- 엔진브레이크는 기어 고정으로 950–2,250 rpm을 쟀습니다(위 표). 1,100 rpm 아래는 950 rpm 한 점입니다.
- 트레일러 질량(약 8 t, 전체 19.9–20.6 t)과 트레일러 바퀴 브레이크 토크는 찾았습니다. 화물을 실은 상태는 아직입니다.
- 트레일러 실행 내내 `truck.wipers`가 켜져 있었습니다(레인 센서). 비가 왔다면 마찰 한계 값(브레이크 1.0, 큰 횡가속)이 달라질 수 있어, 와이퍼가 꺼진 날 같은 계단을 다시 돌려 비교합니다.
