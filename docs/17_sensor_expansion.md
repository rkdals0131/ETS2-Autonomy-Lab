# 센서 확장 계획

현재 입력은 독립 RGB-D 4뷰, 깊이 라이다 3개, SDK 자차 상태와 차량 GT입니다. 추가 센서는 IMU·휠·GNSS부터 만들고 레이더·트레일러 각도를 연결합니다.

## 우선 작업

- **각속도 단위:** SDK `truck.local.velocity.angular`는 회전/초입니다. `bridge/windows/messages.cpp`는 현재 축만 변환해 `angular_velocity_base_radps`에 넣습니다. ROS 경계에서 2π를 곱하고 기존 bag의 각속도 해석에 버전 차이를 기록합니다.
- **속도 기준점:** SDK 선형 속도는 질량중심 기준입니다. 센서 장착점 속도에는 `omega × r`를 적용합니다.
- **라이다 단색:** 실제 ROS 메시지의 유효 range 분포와 Foxglove의 Color map·range·min/max를 대조합니다. `<distance>` 색상과 비교해 값 전달과 표시 범위를 구분합니다.

## 센서 구성

| 센서 | 측정 생성 | 초기 주기 | ROS 출력 |
| --- | --- | --- | --- |
| IMU | 섀시 물리 속도·회전, 장착점 보정, specific force | 물리 갱신률 확인 후 약 60 Hz | sensor_msgs/Imu |
| 휠·조향 | SDK 바퀴 회전속도와 실제 바퀴 조향 | 물리 갱신률 | 바퀴 측정, nav_msgs/Odometry |
| GNSS/RTK | 안테나 월드 위치·지리좌표 변환, 상태별 오차 | 5–10 Hz | sensor_msgs/NavSatFix, RTK 상태 |
| 레이더 | 상대 위치·시선속도, 탐지 확률·가림 | 10–20 Hz | 객체 탐지 목록 |
| 굴절각 | 트랙터와 트레일러 연결부 상대 자세 | 20–60 Hz | 각도·각속도와 GT |
| 초음파·자기계 | 근접 거리·자기장 측정 모델 | 후속 | Range / MagneticField |

주기는 초기 설계값입니다. 물리 표본보다 높은 발행률에는 보간 여부를 명시합니다. 측정 stamp는 시뮬레이션 시각이고, 지연은 별도 전달 지연으로 적용합니다. pause 중에는 센서 적분과 바이어스 시간 전개도 멈춥니다.

## IMU

첫 IMU는 섀시의 실물 장착 가능한 지점에 고정합니다. 질량중심의 월드 속도·각속도와 같은 시각의 장착 변환으로 계산합니다.

```text
a_sensor = d(v_COM)/dt + alpha × r + omega × (omega × r)
f_sensor = R_world_sensor^T (a_sensor - g_world)
gyro_sensor = R_world_sensor^T omega
```

SDK 가속도는 차량축 속도 차분의 10-step 평균입니다. 월드 가속도를 만들 때 필요한 회전 항과 센서 위치 보정을 별도로 처리합니다. 물리 시각별 속도를 우선 사용하고, SDK 평균값의 역필터링은 하지 않습니다. 캐빈 IMU는 상대 운동을 추가하는 후속 구성입니다.

`imu/data_raw`는 가속도·각속도를 제공하고 orientation covariance 첫 값을 -1로 둡니다. 자세 추정은 센서 융합 결과로 발행합니다. 수평 정차 시 위쪽 가속도는 +g입니다. 백색잡음·시간 상관 바이어스·장착 오차와 공분산을 함께 설정합니다. [ROS IMU 규약](https://github.com/ros-infrastructure/rep/blob/master/rep-0145.rst).

## 휠 오도메트리

SDK 바퀴 각속도는 회전/초, 조향은 회전 단위입니다. rad/s·rad로 변환합니다. 운전자 `truck.input.steering`은 정규화 입력이므로 바퀴각과 별도 항목으로 둡니다. 바퀴 반지름과 차량 기하로 주행 거리를 적분하고, 반지름 편차·양자화·슬립을 측정 모델에 추가합니다.

물리 GT pose는 평가용으로 유지합니다. 휠 오도메트리는 바퀴 측정만 적분합니다.

## GNSS와 RTK

안테나는 캐빈 지붕에 부착하고 캐빈 서스펜션 운동을 반영합니다. 기준 위도·경도·타원체 고도와 북쪽 방향을 설정해 게임의 미터 좌표를 가상 지리좌표로 변환합니다. 게임 도시와 실유럽 지도 정합은 별도 지리 보정 작업입니다.

이상적 위치에서 시작해 RTK fixed·float·일반 측위·수신 불가를 추가합니다. 각 상태에 시간 상관 위치 오차, 공분산, 지연, 복구 시간을 둡니다. 터널·차폐 조건을 실제 맵에서 읽기 전에는 명시한 시나리오로 상태를 전환합니다. 위성 궤도·반송파 연산은 후속 범위입니다.

NavSatFix에는 WGS84 위치와 ENU 공분산을 넣고, fixed/float·보정 정보 나이는 별도 상태로 보냅니다. [NavSatFix](https://github.com/ros2/common_interfaces/blob/jazzy/sensor_msgs/msg/NavSatFix.msg), [NavSatStatus](https://github.com/ros2/common_interfaces/blob/jazzy/sensor_msgs/msg/NavSatStatus.msg).

## 레이더와 트레일러

레이더는 우선 차량 GT에서 거리·방위·시선속도를 계산합니다. 센서 장착점 속도를 빼고 FOV·거리·가림·탐지 확률을 적용합니다. 깊이 소스와 레이더 원점이 다르면 해당 원점의 가림을 별도로 확인합니다. 관측 범위 밖은 가시성 미상으로 남깁니다. 반사 강도는 재질 측정 근거가 생길 때 추가하고, 클래스별 상수는 합성 모델로 표시합니다.

트레일러는 실제 연결부 자세와 각도를 확보한 뒤 잡음이 있는 굴절각 센서와 GT를 함께 제공합니다. 외판·굴절 가림과 모델 제출 여부를 동일 주행에서 확인합니다.

## 구현과 확인 순서

1. 단위·기준점 수정과 라이다 색상 확인.
2. 이상적 IMU·휠·GNSS와 고정 TF, 실제 물리 갱신률 확인.
3. 정차·직진·일정 선회·제동에서 측정값을 확인하고 위치 추정 연결.
4. 잡음·바이어스·지연·수신 불가를 추가하고 같은 기록으로 재현.
5. M8 입력과 GT ACC/LCC, 전방 레이더 연결.

GT, 이상적 측정, 오차가 있는 측정, 추정 결과는 별도 토픽으로 둡니다. 난수 seed와 센서 설정을 기록해 재생 실험을 재현합니다. 센서 수치 생성은 Windows 중계기에서 수행하고 DLL은 같은 물리 시각의 원본 상태를 제공합니다.
