# BEV와 E2E 연구 진행

처음부터 대형 VLA 모델을 올리는 것보다, 센서와 제어를 연결한 작은 닫힌 루프를 먼저 만드는 방향을 제안합니다. VLA는 언어까지 입력에 포함하는 별도 선택이며 현재 목표의 필수 구성은 아닙니다.

## 관측과 내부 정답

ETS2LA 플러그인에서 읽을 수 있는 주변 차량·신호·경로는 센서 인식 결과와 다릅니다. 이 정보를 어디에 쓰는지 실험별로 구분합니다. [플러그인 인터페이스](https://github.com/ETS2LA/plugin)

| 정보 | 센서 기반 정책의 기본안 | 다른 용도 |
| --- | --- | --- |
| 동기화된 카메라 영상 | 관측 입력 | 기록·진단 |
| 속도·자차 운동 상태 | 관측 입력 후보 | 제어·좌표 정합 |
| 경로 안내 | 허용할 정보 수준을 정의 후 사용 | 목표 경로 평가 |
| 게임 depth | 초기 기하 파이프라인에 사용 | RGB 모델의 감독 신호·비교 |
| 주변 차량의 정확한 pose | 기본 RGB 정책 입력에서 제외 | 라벨·추적 평가·비교 제어기 |
| 신호등 내부 상태 | 기본 RGB 정책 입력에서 제외 | 인식 정답·규칙 평가 |
| 미래 상태·실제 미래 궤적 | 현재 정책 입력에서 제외 | 미래 예측 학습의 목표값 |

'카메라 E2E' 결과를 말할 때 내부 정답을 몰래 입력하지 않습니다. 이를 위해 추론 입력을 만드는 코드와 평가용 정답을 읽는 경로를 분리합니다. metadata에 정답을 쓰지 않았다고 적는 것만으로 분리가 입증되지는 않습니다.

## 제안하는 진행 단계

1. 기본 관측과 제어를 연결합니다. 단순한 도로에서 조향·속도 명령과 수동 해제가 동작해야 합니다.
2. RGB와 게임 depth를 이용해 차량 좌표의 점군·BEV를 만듭니다. 카메라 사이의 정합을 먼저 확인합니다.
3. 사람 운전 또는 명확히 구분한 비교 제어기로 짧은 시연 데이터를 기록합니다.
4. 이미지와 자차 상태에서 짧은 미래 경로를 예측하는 작은 모델을 시도합니다.
5. 경로 추종 제어기를 연결하고 실제 게임에서 닫힌 루프로 평가합니다.
6. 충분한 센서·성능·데이터가 확보되면 다중 카메라 시간 모델과 더 넓은 도로 상황으로 확장합니다.

미래 경로를 학습하고 저수준 제어를 별도로 두는 것은 중간 설계안입니다. 최종적으로 영상에서 조향·가감속까지 직접 학습할지도 비교할 수 있습니다. 현재 특정 모델이나 체크포인트를 선택한 상태는 아닙니다.

## 데이터 수집

같은 장면의 관측과 그 이후 적용한 행동을 시간으로 연결합니다. 기록된 사람이 누른 키와 게임에 실제 적용된 조향값은 다를 수 있으므로 구분합니다.

학습·검증은 연속 주행의 거의 같은 프레임이 양쪽에 섞이지 않게 run·경로·조건 단위로 나눕니다. 노면, 기상, 주야간, 차량·트레일러 구성과 교통 조건은 필요한 범위에서 확장합니다. 초기부터 모든 조건을 채우는 대규모 코퍼스를 만들지는 않습니다.

공개 모델을 도입할 때는 입력 해상도와 카메라 배치, 좌표계, 도메인 차이, Windows 의존성과 VRAM을 먼저 확인합니다. '6개 카메라를 쓴다'는 공통점만으로 호환된다고 가정하지 않습니다.

## 성능과 평가

게임과 추론이 동일 GPU를 사용합니다. 우선 모델을 작게 시작하고, 학습 실행은 게임의 실시간 운전과 분리하는 작업 기본안을 사용합니다.

처음 볼 수치는 다음과 같습니다.

- 실제 관측에서 명령 적용까지의 지연.
- 차로 유지와 목표 속도 추종의 오차.
- 충돌·차선 이탈·사용자 개입과 그 장면.
- 정지 신호·선행차 상황에서의 실제 반응.
- 게임 프레임 타임과 추론 실행 시간이 서로 미치는 영향.

오프라인의 작은 예측 오차만으로 게임에서 안정적으로 운전한다고 판단하지 않습니다. 반대로 초기 센서 개발 단계에 종합 자율주행 평가 시스템을 먼저 만들 필요도 없습니다. 변경한 중심 경로를 짧은 실제 주행에서 확인합니다.
