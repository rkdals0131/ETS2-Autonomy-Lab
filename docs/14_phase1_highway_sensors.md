# Phase 1 고속도로 센서 리그

고속도로 ACC·차로 유지·사각지대 감시를 위해 트랙터에 전방 협각·광각과 좌우 측후방 포드를 배치합니다. 램프·톨게이트는 운전자가 맡고 차로 변경은 운전자 지시 방식으로 확장합니다.

## 현재 FH4 배치

현재 차량은 FH4 `vehicle.volvo.fh16_2012` 4x2입니다. 설정 원본은 [phase1-highway-fh4-private.json](../ot/presets/phase1-highway-fh4-private.json)입니다. SDK 구동축 바퀴 2·3으로 base_link를 계산합니다. 기존 FH5 프리셋은 과거 측정 참조로 남기며 현재 기본 설정에서는 선택하지 않습니다.

| 카메라 | 슬롯 | base_link x/y/z m | yaw / pitch | HFOV | 출력 |
| --- | --- | --- | --- | --- | --- |
| C_FN | 3 | 5.21335 / -0.00026 / 3.04434 | 0 / -1.5° | 30° | 1280×720 |
| C_FW | 4 | 같은 전방 원점 | 0 / -8° | 120° | 1280×720 |
| C_RL | 6 | 4.47579 / +1.56 / 2.64417 | +145 / -12° | 100° | 960×544 |
| C_RR | 7 | 4.47579 / -1.56 / 2.64417 | -145 / -12° | 100° | 960×544 |

전방은 선바이저 로케이터 높이의 브래킷을 캐빈 메시의 가장 앞쪽 경계보다 35mm 앞으로 뺍니다. 측면은 미러 전체 메시 경계보다 뒤쪽 35mm, 좌우 외곽 밖에 놓는 브래킷입니다. 실제 외판 표면에서 법선 방향으로 정확히 35mm를 띄운 ray 보정은 아닙니다. 설치 자산의 sleeper/globe/globe_xl 세 캐빈은 전방 경계와 관련 로케이터가 같고, stock mirror_01/02/03도 같은 외곽 경계여서 이 장착점은 그 변형들에 공통입니다. 네 센서는 캐빈 운동을 따릅니다.

측면 프리셋 요청 크기는 960×540이고 현재 엔진의 실제 출력은 960×544입니다. 표에는 실제 출력 크기를 적었습니다. CameraInfo는 해당 pass의 실제 projection·viewport를 사용합니다.

센서용 camera/drawable은 DLL이 함께 소유하고 0·1·2·5를 템플릿으로 사용합니다. `ot/sensorN` 독립 출력과 alias 0xffff로 기본 미러 텍스처를 분리합니다. 2026-10-10 현재 FH4의 실제 native pass namespace는 0·1·2·5로 관측됐습니다. camera 객체 존재만으로 해당 슬롯이 렌더되는 것은 아닙니다.

FH4 실제 ROS 실행에서 네 JPEG·CameraInfo와 세 라이다 preview 점군을 각각 53개, 약 10.46Hz로 받았습니다. 전방과 좌우 측후방의 대표 영상을 확인했으며 측면 가장자리에는 자차 일부가 보입니다. 동축 CameraInfo·TF도 전달됐습니다. 이 짧은 정차 관측은 트레일러 굴절·큰 캐빈 운동·모드 부품의 보정을 입증하지 않습니다.

## 라이다와 상태 센서

전방 L_F는 C_FN·C_FW의 같은 원점에서, L_PL·L_PR은 각각 측면 포드 원점에서 깊이를 샘플링합니다. [라이다 패턴](15_virtual_sensors.md).

IMU·휠·휠 오도메트리·가상 GNSS는 ROS에 연결돼 있습니다. 현재 IMU·GNSS는 섀시에 고정됩니다. 트레일러 굴절각은 실제 연결부 상태를 확보한 뒤 추가합니다. [측정 모델](17_sensor_expansion.md).

## 차량 변경과 캘리브레이션

`bridge/windows/vehicle_profile.cpp`가 SDK truck ID를 프리셋의 `truck_id`와 대조하고 SDK 바퀴 위치·반지름에서 base_link를 계산합니다. 기준 축·바퀴별 위치·반지름·조향/구동 여부를 `/ets2/sensors/config`에 함께 보냅니다. 프리셋의 `vehicle_configuration`은 설명이며 실제 구성 검사에 사용하지 않습니다. 같은 FH4 ID에서도 캐빈·섀시·미러·선바이저 변경은 장착점에 영향을 줍니다. 실행 중 SDK truck generation이 바뀌면 릴레이를 종료하고 재시작을 요구합니다.

현재 FH4를 사용하며, 다른 차량·모드 부품을 추가할 때 다음 순서로 보정합니다.

1. SDK 바퀴 기하와 실제 섀시·캐빈·미러·장착 부품을 확인합니다. `base_link_wheels`로 기준 축을 지정합니다. 다중 구동축 차량은 기준 축을 하나 선택해야 합니다.
2. native 미러 슬롯을 확인하고 센서 camera/drawable을 같은 빈 index에 배치합니다. 현재 자동 슬롯 할당은 구현돼 있지 않습니다.
3. 차체 메시·로케이터에 맞춰 광학 중심을 외판 바깥에 배치합니다. 부모 좌표계와 위치·회전을 정하고 근접 가림을 RGB·depth·메시 교차로 확인합니다.
4. 실제 pass의 projection·viewport에서 CameraInfo를 생성하고 장착 변환을 TF로 확인합니다. 해상도 변경 시 축소 영상의 CameraInfo도 함께 바뀝니다.
5. 캐빈 운동·조향·연결 트레일러에서 가림과 투영 정합을 확인한 뒤 해당 구성의 프리셋을 사용합니다.

카메라 내부 보정값은 실제 투영에서 자동 생성됩니다. 외부 장착 보정은 프리셋에 저장하고 `bridge.local.json`의 `rig`·`lidar`로 선택합니다. 카메라·라이다는 현재 캐빈 부착만 지원하며 IMU·GNSS는 base_link 기준 평행 축과 이동량만 설정할 수 있습니다.

## 센서 선택

`bridge.local.json`의 `slots`로 기존 카메라를 선택하고 ROS 구독으로 필요한 출력을 켭니다. `slots: []`는 상태 센서만 실행합니다. 라이다 패턴의 소스가 빠지면 해당 라이다가 발행되지 않습니다. 현재 토픽 목록은 고정돼 있어 미선택 카메라의 토픽도 보입니다. 새 이름·추가 카메라는 [토픽 계약과 출력 매핑](03_system_design.md#코드-경계)을 함께 확장합니다.

## 주행 확인

트레일러 연결·굴절, 큰 캐빈 운동, 고개 회전, 주야간·터널·곡선 구간에서 시야와 누락을 확인합니다. 전방 150m 이상 차량과 측후방 인접 차로가 주요 관측 영역입니다.
